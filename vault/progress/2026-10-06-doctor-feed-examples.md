# 2026-10-06: doctor, feed, game accessibility, examples

## What changed

- **#24 `doctor`** in `bakjob-surdeg`: checks `CLAUDE.md`, enabled plugins
  (and ones that should be on, and copied skills shadowing a plugin), the
  facts each plugin needs, vault freshness, tracker hygiene and git basics;
  reports a table and fixes only what the user approves. In `bakjob-surdeg`
  rather than `bakjob-core` so it works in projects that aren't set up yet.
- **#25 `feed`** in `bakjob-surdeg`: re-asks only the interview rounds the
  user picks, with today's answers as the defaults, shows before → after,
  applies only those parts of `generate.md`, and offers migrations (todo
  list → issues, tracker → tracker, vault none → light/full). Bootstrap
  points at it when a project was bootstrapped before.
- **#26 `game-accessibility`** in `bakjob-game`: a checklist tagged by the
  Game Accessibility Guidelines' tiers, used while building and as an
  audit; bootstrap asks for the target tier.
- **#27 `examples/`**: a Godot game (GitHub Issues, full vault, three
  plugins) and an Astro site (no tracker, straight to main, light vault),
  generated by running the template through `generate.md`'s rules with a
  script, then writing the fact files by hand from the answer sheets.

## What the dry run found

Generating the examples was the first run of `generate.md` end to end, and
it found three gaps, fixed here:

- `[DOCS_DIR]` filled with `vault/` produced `vault//hard-rules.md` paths;
  `generate.md` now says how to fill it.
- A light vault had nowhere to keep the answer sheet, so `feed` would have
  had nothing to start from; it now goes to `DOCS/setup.md`.
- The vault template's decision example `[NNNN](./NNNN-slug.md)` tripped the
  placeholder check bootstrap runs on its own output.

## Versions

`bakjob-surdeg` 0.4.0, `bakjob-game` 0.2.0.

# Examples

Two projects as `bakjob-surdeg`'s bootstrap leaves them, generated by
following its `generate.md` step by step with a fixed set of answers. Each
folder is what the root of a new repo would contain right after bootstrap,
before any code is written. One difference: bootstrap also copies the chosen
skills and agents (and `bootstrap`, `feed`, `doctor`) into `.claude/skills/`
and `.claude/agents/`; those copies are left out here, since they are
identical to the folders under `plugins/`. The answers are in each project's
`vault/progress/2026-10-06-bootstrap.md` or `docs/setup.md`.

| | [`godot-game/`](godot-game/) | [`astro-site/`](astro-site/) |
|---|---|---|
| Project | Ember Hollow, a 2D action-roguelike | Kvarngatans Bageri, a bakery website |
| Stack | Godot 4.5, GDScript | Astro 5, TypeScript, pnpm |
| Tracker | GitHub Issues, full review loop | none: a todo list in `docs/status/todo.md` |
| Git | feature branches + PRs; Claude opens PRs, you merge | straight to `main`; Claude commits, asks before pushing |
| Vault | full, in `vault/`, with `game-design/` | light, in `docs/`, answers in `setup.md` |
| Plugins (copied in) | `bakjob-core`, `bakjob-github`, `bakjob-game` | `bakjob-core`, `bakjob-web` |
| Extras | Git LFS, CI with GUT, gdformat hook | Prettier hook, Netlify deploy notes |

Things worth comparing:

- **`CLAUDE.md`**: the same template, rewritten differently by the answers
  (the tracker section becomes "Todos", the git workflow flips, push back is
  shortened).
- **`.claude/settings.json`**: the permissions for "Generous" vs
  "Standard", the formatter hook per stack. No plugin keys: the project
  depends on nothing outside its folder.
- **`running.md`, `hard-rules.md`, `quality-targets.md`**: the facts the
  plugins read instead of carrying placeholders.

*The `CLAUDE.md` files here only describe these example projects; they
don't apply to working on this repo.*
